    LOOK INSIDE A CPU CORE

    A CPU core is huge because it's smart. Most of it is brain: parts that guess which way your code will branch, reorder instructions, and juggle a dozen tasks. Then there's cache, a private stash of memory.

    The part that actually does the math, the ALU, is one tile out of sixteen.

    But every pixel follows the same recipe.
    Why does every worker need its own brain?

    ONE SHOUT, SIX DIFFERENT PIXELS

    An ALU (Arithmetic Logic Unit) is the circuit that actually does math: add, multiply, compare. Beside it sit a few registers, its own tiny notepad. Each ALU starts with its own pixel's x and y written in it.

    The control unit shouts what to do. Every ALU does it to its own numbers. Same instruction, different data.

    these 6 pixels · row y = 9
    CONTROL UNIT SHOUTSget ready…step 0 / 8

    Notice the if steps. When the condition is false for some ALUs, they just sit that step out. Nobody runs ahead, everyone stays in lockstep.

    What can renderPixel depend on? Only its inputs: its own x, y, values that are the same for every pixel (here SUN and SEA; in a real game the time, the camera, the lights), and data it reads from memory (like textures). It outputs one color. It never peeks at another pixel's answer, so any pixel can run on any ALU, in any order. That's what makes it parallel.

    AI is a giant grid of multiply-adds

    Every answer cell needs only its own row and column. No cell waits for any other cell. Sound familiar? It's pixels all over again.

    RUN A NEURAL NETWORK LAYER

    A tiny layer of 24 neurons, each with 16 weights (the columns of B), looking at 24 inputs of 16 numbers each (the rows of A). Every answer cell in C is one neuron's response to one input: 576 answers.

    Watch the gold markers: that's step k, one multiply-add. The CPU walks one row and one column at a time. Your chip lights up many rows and columns at once, and all their gold markers move together, in lockstep.

    function answerCell(i, j) → number
  sum = 0
  repeat k = 1 … 16:        ← one step each
    sum = sum + A[i][k] × B[k][j]
  return sum
